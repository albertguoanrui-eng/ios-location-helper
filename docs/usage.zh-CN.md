# 定位助手：手机端完整使用教程（一步一步操作）

> **历史文档：项目已于 2026-09-11 归档。** 当前测试设备未实现系统定位修改，下方操作和检查记录不构成可用承诺。请先阅读 [归档说明](ARCHIVED.zh-CN.md)。

更新日期：2026-09-11。适用项目：**albertguoanrui-eng/ios-location-helper**，当前面板版本 **0.1.2**。

本教程从你目前遇到的“在小火箭点击下载后没有出现内容”开始，按顺序完成导入、证书、面板、伦敦坐标、地图验证和停止操作。日常使用只操作 iPhone；GitHub 分发版本不需要连接电脑，也不需要安装另一个签名 App。

**完成安装不等于定位一定能改变。iOS 27.0 RC 尚未完成真机验收；如果系统不发出可解密的 WLOC 请求，或不采用修改后的响应，本模块无法让地图蓝点移动。**

小火箭具体版本尚未提供。下面的模块入口参考上游使用说明，证书信任入口参考 Apple 文档；不同版本的菜单布局可能不同。界面找不到对应入口时，按本教程的截图反馈步骤处理，不把相邻的“添加订阅”“添加配置”当成“添加模块”。

## 一、准备与下载检查

### 步骤 01：记下设备和小火箭版本

打开 iPhone「设置 → 通用 → 关于本机」，记录 iOS 版本及能查看到的构建号；在 Shadowrocket 的设置或关于页面记录 App 版本。如果那里没有版本信息，也可查看 iOS「设置 → 通用 → iPhone 储存空间 → Shadowrocket」。

**检查结果：** 你能提供类似“iOS 27.0 RC，构建号……；Shadowrocket ……版”的信息。后续报错时用这份记录，不需要反复猜测菜单版本。

### 步骤 02：确认手机当前能正常联网

保持你平时能正常上网的小火箭配置和节点，打开 Safari 访问本项目仓库：

<https://github.com/albertguoanrui-eng/ios-location-helper>

**检查结果：** 能看到仓库名称和 README。仓库网页能打开，只说明 `github.com` 可达，还不能证明模块所在的下载域名可达。

### 步骤 03：复制 CDN 模块地址

考虑到你已经遇到原地址下载无反应，本教程先使用 CDN 入口。复制下面**完整的一行**，不要带上代码框标记、前后空格或换行：

```text
https://cdn.jsdelivr.net/gh/albertguoanrui-eng/ios-location-helper@main/module/location-helper-cdn-0.1.2.sgmodule
```

**检查结果：** 地址以 `https://` 开头，以 `location-helper-cdn-0.1.2.sgmodule` 结尾。它是模块文件地址，不是 GitHub 的 `blob` 文件预览网页，也不是手机控制面板地址。

### 步骤 04：先在 Safari 测试这条地址

把步骤 03 的地址粘贴到 Safari 地址栏，前往该地址。

**检查结果：** 正常响应是配置文字，其中应出现：

```ini
#!name=定位助手 · CDN 下载入口
```

正文还应包含 `[Script]`、三条 `Location Helper` 脚本配置和 `[MITM]`。Safari 可能直接显示文字，也可能让你查看或保存文件；**没有自动弹出下载窗口不代表没有内容**。

**如果页面空白、一直加载或报错：** 暂时不要继续装证书，先做步骤 05；HTTPS 解密证书不能解决模块下载域名不可达的问题。

### 步骤 05：下载失败时换原始入口测试

若 CDN 地址打不开，再在 Safari 测试 GitHub Raw 原始入口：

```text
https://raw.githubusercontent.com/albertguoanrui-eng/ios-location-helper/main/module/location-helper-0.1.2.sgmodule
```

其首行应为：

```ini
#!name=定位助手 · 本地控制与诊断
```

**检查结果：** 选择能返回完整配置的那个地址，记住它用于下一阶段。原始入口名称中的“本地”表示控制发生在手机内，并不要求电脑参与。

如果两个地址都打不开，先切换手机当前网络或检查现有代理连接，再分别重试一次。如果仍失败，保存错误提示，直接做步骤 41。不要仅因为开发机可以下载，就判断手机网络也已经正常。

## 二、导入模块

### 步骤 06：进入小火箭的模块列表

回到 Shadowrocket，打开底部「配置」，寻找「模块」入口。部分界面可能需要先打开当前正在使用的配置详情，再寻找模块管理。

**检查结果：** 你进入的是管理模块的页面。模块是附加到当前配置中的规则，不是节点或机场订阅。

**如果找不到“模块”：** 停在这一步，截取当前配置页和当前配置详情页，按步骤 41 反馈。由于你的 Shadowrocket 版本未知，不能断言每台设备的按钮都在同一位置。

### 步骤 07：在模块页面新增 URL

在模块管理页面使用「＋」或新增入口；如果出现来源选择，选择「来自 URL」或含义相同的网络地址选项。

**检查结果：** 出现用于输入模块地址的字段。有些版本可能直接显示地址输入框和“下载”，不一定另有“来自 URL”菜单。

### 步骤 08：粘贴步骤 04 或 05 验证过的地址

在地址字段粘贴完整模块 URL，核对结尾仍然是 `.sgmodule`。

**检查结果：** 字段中只有一条地址。不要粘贴模块正文、仓库首页、`source.zip` 地址或 `https://gs-loc.apple.com/wloc-helper/`。

### 步骤 09：点击下载或保存

点击当前页面的「下载」「完成」或「保存」按钮，等待本次操作结束，再返回模块列表。

**检查结果：** 不是看到节点列表增加一条节点，而是模块列表出现步骤 10 中的项目。

### 步骤 10：确认模块确实出现在列表

检查模块列表是否出现以下名称之一：

| 使用的地址 | 模块名称 |
| --- | --- |
| CDN 入口 | 定位助手 · CDN 下载入口 |
| GitHub Raw 入口 | 定位助手 · 本地控制与诊断 |

**如果点击“下载”后什么也没出现，按下面顺序检查：**

1. 回看当前页面是不是步骤 06 的模块管理，而不是整份配置或订阅下载页面。
2. 回到 Safari，用**同一个完整地址**重复步骤 04。Safari 成功只证明 Safari 路径可达，小火箭自身下载仍可能失败。
3. 在小火箭的日志或活动记录中，检查刚才下载时间附近有没有域名解析失败、连接超时、TLS 错误、HTTP 403/404 等提示；不同版本日志入口不同，没有看到日志也记录下来。
4. 换另一个入口重试一次。原入口和 CDN 入口最终只启用一个。
5. 两个入口在小火箭里都无新增项时，记录实际按钮和页面，按步骤 41 发截图。这时不能把“已经点过下载”记为安装成功，也不应跳到地图验证。

### 步骤 11：启用刚刚导入的模块

使用模块条目对应的开关、勾选或启用操作，确认该模块在当前使用的配置中生效。

**检查结果：** 模块显示启用。具体标识可能是开关或勾选，以当前版本界面为准。

### 步骤 12：停用之前的定位模块

如果之前导入过其他 WLOC 定位模块，先停用它们；本项目原始入口和 CDN 入口也只保留一个处于启用状态。

**检查结果：** 当前只有本项目的一个定位模块负责改写该接口。保留你原有上网节点和其他业务配置；这一步不需要删除整份配置。

### 步骤 13：检查模块内的三条脚本地址

若模块详情提供配置正文或脚本列表，确认包含三条脚本：

```text
Location Helper Panel
Location Helper Observe
Location Helper Rewrite
```

使用 CDN 模块时，三条 `script-path=` 均应以以下地址开头：

```text
https://cdn.jsdelivr.net/gh/albertguoanrui-eng/ios-location-helper@main/module/
```

**检查结果：** 没有 `127.0.0.1` 或 `192.168.*` 这类旧本地下载地址。CDN 版本不只替换模块地址，也替换三份脚本的下载来源。

若需要单独判断脚本下载是否可达，可在 Safari 逐个打开以下地址。看到 JavaScript 文字是正常的，不需要把脚本正文手动粘贴到坐标输入框：

- [panel.js：控制面板脚本](https://cdn.jsdelivr.net/gh/albertguoanrui-eng/ios-location-helper@main/module/panel-0.1.2.js)
- [observe.js：请求观测脚本](https://cdn.jsdelivr.net/gh/albertguoanrui-eng/ios-location-helper@main/module/observe-0.1.2.js)
- [rewrite.js：响应改写脚本](https://cdn.jsdelivr.net/gh/albertguoanrui-eng/ios-location-helper@main/module/rewrite-0.1.2.js)

模块存在不等于三份脚本已经下载并执行；后面的面板和诊断会继续验证运行过程。

## 三、HTTPS 解密和证书

### 步骤 14：打开当前配置的 HTTPS 解密设置

在「配置」页面找到当前正在使用的配置，打开详情或右侧「ⓘ」，寻找「HTTPS 解密」。有些版本会把它放在其他设置位置。

**检查结果：** 你看到的是 HTTPS 解密设置及域名、证书相关选项。上游教程记录过 `2.2.88(3308)` 的“配置 → 当前配置右侧 ⓘ → HTTPS 解密”路径；这不是对所有版本界面的保证。[上游入口参考](https://github.com/mekos2772/ios-location-spoofer/blob/main/%E4%BD%BF%E7%94%A8%E6%95%99%E7%A8%8B.md)

### 步骤 15：开启 HTTPS 解密

打开 HTTPS 解密开关，并按当前界面要求保存。

**检查结果：** 开关保持开启。不要把小火箭首页的连接开关当成 HTTPS 解密开关，它们作用不同。

### 步骤 16：核对定位域名

检查当前配置及已启用模块所覆盖的解密域名，确认包含以下 5 个。模块已使用追加方式声明这些域名；若界面不显示模块合并结果，先查看模块正文，不直接认定导入失败。

需要手动补充时，复制这一行到域名设置中：

```text
gs-loc.apple.com,gs-loc-cn.apple.com,gsp-ssl.ls.apple.com,bluedot.is.autonavi.com,bluedot.is.autonavi.com.gds.alibabadns.com
```

**检查结果：** 域名无 `https://`、无路径，逗号分隔。保留原有需要的域名，不用把全部域名设置成通配解密。

### 步骤 17：查看小火箭当前使用的 CA 证书

在 HTTPS 解密设置中打开「证书」或含义相同的选项。

**检查结果：** 确认有没有现有 CA。若已有并且已经安装、信任，可以跳过重新生成，继续步骤 20–22 核对；重复生成 CA 会使旧证书不再对应新 CA。

### 步骤 18：没有 CA 时生成本机证书

仅在确实没有可用 CA 时，使用小火箭提供的生成 CA 操作。

**检查结果：** 小火箭能够显示当前证书信息或提供安装入口。本项目不提供需要你另行下载的共享 CA 文件。

### 步骤 19：从小火箭发起证书安装

使用当前证书的安装操作。如果 Safari 或系统提示下载描述文件，确认这是刚从自己小火箭发起的证书安装，再按提示允许下载。

**检查结果：** 出现描述文件已下载或系统安装入口。此处下载的是证书描述文件，和前面的 `.sgmodule` 是两种不同文件。

### 步骤 20：在 iOS 设置里安装描述文件

打开 iPhone「设置」，使用“已下载描述文件”入口，或进入「通用 → VPN 与设备管理」，找到刚下载的 Shadowrocket 证书描述文件，按系统提示完成安装。

**检查结果：** 系统中能查看到已安装的描述文件。如果列表没有它，返回步骤 19 检查证书下载，而不是重复导入定位模块。

### 步骤 21：启用根证书完全信任

打开：

```text
设置 → 通用 → 关于本机 → 证书信任设置
```

找到刚安装、与小火箭当前 CA 对应的根证书，为它启用完全信任，并按系统提示确认。

**检查结果：** 对应证书的信任开关开启。Apple 明确说明：手动安装证书描述文件，不会自动获得 SSL/TLS 信任；需要单独开启。[Apple 官方说明](https://support.apple.com/zh-cn/102390)

### 步骤 22：回到小火箭核对保存状态

确认当前配置仍为你刚设置的那份、HTTPS 解密保持开启、定位模块仍启用。

**检查结果：** 没有因为切换配置而回到另一套未启用模块的设置。若后续 Safari 出现证书错误，回查步骤 17–21 的 CA 对应关系和信任状态，不把绕过浏览器警告当成安装完成。

## 四、打开控制面板

### 步骤 23：重新连接小火箭

在小火箭首页断开并重新开启连接，让当前设置重新加载。

**检查结果：** 小火箭显示连接正常。首次创建 VPN 配置时按系统提示处理；仅有 VPN 连接成功，仍不能证明 HTTPS 解密和定位改写成功。

### 步骤 24：在 Safari 打开手机控制面板

把下面的完整地址粘贴进 Safari 地址栏并前往，保留结尾的 `/`：

```text
https://gs-loc.apple.com/wloc-helper/
```

**检查结果：** 出现“定位助手”中文页面，有目标位置输入框和诊断区域。这个路径由小火箭脚本在手机内返回，不是一个不依赖模块就能访问的普通控制网站。

**如果出现 Apple 页面、404、证书错误或空白：** 先回查模块启用、`panel.js` 下载、HTTPS 解密和证书；不要把面板地址再作为模块 URL 导入。

### 步骤 25：确认控制接口已连接

查看诊断区域的“本机控制接口”。

**检查结果：** 显示“已连接”，保存按钮可操作。首次使用、没有之前持久化设置时，顶部应显示“改写已关闭”。已有保存记录的设备可能显示上一次开关状态，以实际读到的配置为准。

如果显示“预览模式 · 尚未连接手机”，你打开的是预览页，回到步骤 24 的精确地址。如果显示“无法连接本机模块”，先排查控制接口，不继续填写坐标来判断定位是否生效。


**如果旧版持续提示“模块接口不兼容”，但直接打开状态接口能看到 JSON：** 更新到步骤 03 的 0.1.2 模块，只启用新版，重新连接小火箭，再打开 `https://gs-loc.apple.com/wloc-helper/?v=0.1.2`。确认右上角为 0.1.2。新版随整页读取状态，不再依赖打开页面后的自动状态查询。此前故障的全部根因尚未确认。

如果新版仍失败，展开“连接诊断（不含坐标）”，点击“复制诊断”。连接失败时也可复制，不要重复导入同一版本。记录具体失败字段、页面版本和小火箭版本。

| 新版错误 | 含义和下一步 |
| --- | --- |
| 状态校验失败：… | 显示具体不符合格式的字段；复制连接诊断，不代表 RC 已封堵定位 |
| 接口 config / stop 返回 HTTP … | 修改设置的请求失败，记录完整状态码；点击刷新读取实际存储，避免盲目重复提交 |
| 缺少本项目响应标识 | 可能未命中规则或仍运行旧脚本，核对模块及版本 |
| 返回非 JSON（HTTP …） | 返回了非预期内容，检查脚本命中及原站响应 |
| 本机接口超时 / Failed to fetch | 修改或导出请求未正常完成，刷新整页确认实际状态 |
| 请使用 HTTPS 控制面板 | 地址使用了 HTTP，改用步骤 24 的 HTTPS 地址 |

## 五、设置伦敦并验证

### 步骤 26：点击“伦敦市中心”

在控制面板点击预设按钮“伦敦市中心”。

**检查结果：** 经纬度输入框被填入伦敦坐标。这个按钮只填写表单，还没有提交设置。

### 步骤 27：核对三个数值

逐项核对：

| 输入框 | 填写内容 | 注意 |
| --- | --- | --- |
| 纬度 · Latitude | `51.5074` | 纬度在前 |
| 经度 · Longitude | `-0.1278` | 必须保留负号，表示西经 |
| 水平精度（米） | `25` | 正整数，范围 1–10000 |

**检查结果：** 输入框只有数字，不包含“英国”“°”“W”或中文逗号。坐标采用 WGS-84，纬度范围 −90 至 90，经度范围 −180 至 180。

### 步骤 28：点击“保存并开启改写”

点击保存按钮，等待本机接口返回。页面将自动重新加载，读取已经保存的设置；加载期间不要重复点击。

**检查结果：** 重新加载后，诊断中的“坐标改写开关”为“已开启”；没有新请求时，顶部显示“设置已保存，等待定位请求”。如果系统恰好已有请求，状态也可能直接进入后续阶段。

出现数值错误就返回步骤 27；出现存储或接口错误就先处理错误。**保存成功只证明设置写入了小火箭，不证明地图位置改变。**

### 步骤 29：确认苹果地图可以使用定位

在 iOS 定位服务设置中确认定位服务已开启，并允许“地图”在使用期间获取位置；如果有精确位置选项，确认它符合你的地图测试需要。

**检查结果：** 地图能够请求当前位置。定位权限未授予时，不能用“地图没有蓝点”判断模块失败。

### 步骤 30：在苹果地图请求当前位置

打开苹果地图，点击地图中的当前位置/定位箭头按钮，等待地图完成本次定位。

**检查结果：** 地图尝试显示当前位置。不要仅搜索“伦敦”并把地图画面移动过去；搜索结果标记或地图中心不是设备定位蓝点。

### 步骤 31：记录蓝点的位置

查看代表当前位置的蓝点是否到了伦敦附近，并记下结果：仍在真实位置、已到伦敦、无蓝点，或者出现定位错误。

**检查结果：** 得到一条实际观察记录。此时不需要把包含家庭地址的完整地图截图公开上传。

### 步骤 32：回到控制面板刷新诊断

切回 Safari 的控制面板，点击“刷新诊断”。0.1.2 会重新加载整页，未保存的输入会被当前持久化设置替换；它不会重新提交坐标。

**检查结果：** 能查看当前设置的最近 WLOC 请求时间、响应时间和改写结果。诊断不是累计次数；每次保存会开始一个新的配置版本，旧版本记录不再算本次结果。

### 步骤 33：按实际状态判断停在哪一环

| 面板文字 | 现在能确认的事情 | 下一步 |
| --- | --- | --- |
| 改写已关闭 | 开关仍处于关闭状态 | 回到步骤 28，确认保存返回成功 |
| 设置已保存，等待定位请求 | 配置已保存，但本次设置尚未观测到请求 | 核对模块、当前配置、解密和地图请求；可能涉及缓存或系统没有使用此接口，不能直接下结论 |
| 已收到请求，等待响应 | 请求脚本执行过，尚无本次响应记录 | 查看定位域名的连接与 TLS / MITM 日志 |
| 响应已改写，等待手机验证 | 脚本已处理含坐标的响应 | 对照步骤 31 的蓝点记录，不能只看面板判定生效 |
| 收到响应，但解析失败 | 收到的响应未被本项目可靠解析，已保持原样 | 复制诊断，记录系统构建号；不要把它解释成坐标填错 |
| 定位服务返回异常 | 响应状态异常，本次没有改写 | 结合连接日志排查服务和网络状态 |
| 响应仍被压缩，未改写 | 本次压缩响应保持原样 | 记录诊断；不能通过反复保存坐标解决压缩格式问题 |
| 收到空响应，未改写 | 没有取得足够的响应正文 | 记录本次时间和连接状态后反馈 |
| 响应中没有可改写坐标 | 响应里未找到可用经纬度对子 | 复制诊断；不会把空 Wi-Fi/基站条目算成改写成功 |

**检查结果：** 你能说清“卡在下载、面板、保存、请求、响应还是地图验证”，而不只说“定位不行”。

### 步骤 34：决定是否继续实际 App 验证

只有苹果地图蓝点已经移动时，再打开你原本需要测试的 App，检查其定位结果。

**检查结果：** 分别记录地图和目标 App 的结果。地图已移动不保证所有 App 都采用相同位置来源。

如果面板显示响应已改写，但蓝点没动，可保存诊断后进行一次重启测试：重启手机、重新连接小火箭、打开控制面板确认开关状态，再重复步骤 30–33。重启只是排查缓存的尝试，**不保证解决 iOS 27.0 RC 的系统限制**。仍无效时停止重复尝试并反馈，当前项目不能宣称已经支持这台设备。

<a id="stop"></a>
## 六、停止与恢复

### 步骤 35：在面板点击“停止改写”

回到 Safari 控制面板，点击“停止改写”。

**检查结果：** 顶部显示“改写已关闭”，诊断开关为“已关闭”。这个操作停止后续新响应的改写，不直接调用系统清缓存接口。

### 步骤 36：回到地图检查真实位置

切回苹果地图，再次点击当前位置按钮。

**检查结果：** 检查蓝点是否回到实际位置。不能仅凭面板的“已关闭”就宣布系统缓存已经恢复。

### 步骤 37：面板打不开或地图仍有旧位置时处理

如果面板无法打开，先在小火箭模块列表停用本项目模块，避免继续改写新响应。若地图仍显示旧位置，可在模块停用后重启手机，再检查地图定位。

**检查结果：** 本项目不再参与新响应改写，并另行确认真实位置。停止使用本项目不要求删除整个小火箭配置；同一 CA 可能仍被其他解密模块使用，也不需要为了这个操作删除所有证书。

## 七、更新与反馈

### 步骤 38：需要更新时刷新现有模块

在本项目模块详情使用当前版本提供的更新或重新下载操作。如果没有更新入口，可在确认保存了所需坐标后停用旧条目，再按步骤 06–11 重新导入；新旧条目只启用一个。

**检查结果：** 模块来源和三条脚本地址仍对应你选择的原始/CDN 入口。CDN 缓存可能延迟更新；遇到新版本未同步时，用原始入口交叉检查，不保证添加随意查询参数就能清除所有缓存。

### 步骤 39：更新后再次验证脚本运行

重新连接小火箭，打开步骤 24 的控制面板并刷新诊断。若小火箭提供单独的脚本更新操作，也要确认三份脚本更新完成。

**检查结果：** 面板控制接口连接正常，随后按步骤 26–33 验证。离线脚本缓存行为尚未真机确认，不能以“以前下载过”证明现在一定能离线运行。已导入公开版本后，不需要维持电脑局域网文件服务。

### 步骤 40：复制诊断

在已连接的控制面板点击“复制诊断”。

**检查结果：** 显示诊断已复制，或出现可手动复制的文本框。自动复制不可用时，长按文本框选择并复制全部内容。

本项目导出会省略目标经纬度、请求正文、认证头和完整 URL；它仍包含事件时间与定位服务域名。`systemLocationVerified: false` 表示模块**没有自动验证系统位置的能力**，并不单独证明你的地图一定没有移动。地图结果仍以步骤 31 的观察为准。

### 步骤 41：按模板反馈失败步骤

把下面模板复制到对话中，填入你能确认的信息；没有的项目写“未看到”或“未到这一步”：

```text
卡住的步骤编号：
iOS 完整版本 / 构建号：
Shadowrocket 版本：
使用入口：CDN / GitHub Raw
Safari 打开同一模块 URL：配置文字 / 空白 / 一直加载 / 错误提示
点击下载所在页面：模块管理 / 配置下载 / 无法确认
点击下载后的结果：
模块列表是否出现定位助手：
本机控制接口：已连接 / 未连接 / 面板打不开
坐标改写开关：已开启 / 已关闭 / 未看到
最近请求、响应和改写结果：
苹果地图蓝点：真实位置 / 伦敦 / 无蓝点 / 其他
完整错误提示：
复制诊断：
```

对于你现在的“点击下载后什么也没出现”，最有用的是**下载页面截图、返回后的模块列表截图和小火箭版本号**。如果截图包含机场订阅 URL、节点密码、令牌、证书私钥或家庭地址，先遮挡这些内容。排查下载问题不需要这些秘密，也不需要发送完整未脱敏流量。

## 三个开关，不要混淆

| 位置 | 作用 | 验证方法 |
| --- | --- | --- |
| 小火箭首页连接开关 | 让流量进入当前代理配置 | 小火箭连接状态 |
| 模块启用与 HTTPS 解密设置 | 让匹配规则和解密机制参与处理 | 模块/解密设置及真实请求诊断 |
| 面板“保存并开启改写” | 允许脚本把新 WLOC 响应坐标改成目标值 | 面板配置状态与响应诊断 |

以上设置正确，也仍需单独检查地图蓝点。项目没有读出或替换 GPS 硬件坐标的通用权限。
